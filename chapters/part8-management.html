📊 Chapter 45 — VAPT Project Management

45.1 Pre-Engagement: The Most Critical Phase

Most junior testers jump into scanning on Day 1. Senior managers spend weeks on pre-engagement. This is where you win or lose the engagement.

Pre-Engagement Checklist

  • Signed NDA / MNDA
  • Signed Scope of Work (SOW)
  • Master Service Agreement (MSA)
  • Rules of Engagement (RoE) document
  • LoA — Letter of Authorization to test
  • Insurance — professional indemnity & cyber liability
  • Contact tree (24×7 emergency contact for client)
  • Test windows agreed (off-hours for production)
  • Communication channel established (Slack / Teams)
  • Crisis communication plan (what if something breaks?)
  • Data handling / cleanup agreement
  • Acceptable testing techniques (DDOS? Social eng? Phyiscal?)
  • Deliverables agreed (report format, retest inclusion)
  • Success criteria (no. of findings, severity distribution)

45.2 Scoping Like a Pro

45.2.1 What Goes in Scope?

  • Domains (e.g., *.target.com, api.target.com, admin.target.com)
  • IP ranges (e.g., 203.0.113.0/24)
  • Apps (e.g., iOS + Android binaries, backend API)
  • Network ranges (e.g., internal 10.0.0.0/8)
  • Source code (e.g., .git repo, specific folders)
  • Cloud account(s) (AWS account 1234-5678-9012)

45.2.2 Out-of-Scope (Always Document!)

  • Production payment processing endpoints (PCI compliance issues)
  • Customer data warehouses
  • Third-party SaaS apps (no permission!)
  • DDoS-style stress testing
  • Social engineering of employees without HR sign-off

45.5 Daily Standup With Client

  • What we plan to test today
  • Any blockers / asks

45.7 Real-Life Scenario: When Things Go Wrong

📍 Scenario — Pentest Brought Down Production

A junior tester ran a vulnerability scanner in "intrusive mode" against a client's production banking platform with 5 million concurrent users. The scan generated 100k requests/second. The load balancer crashed. The banking platform was down for 90 minutes. Thousands of customers couldn't pay bills. The junior tester had not read the RoE clearly.

Damage: $50K in remediation + client trust damaged. The junior tester was fired. The pentest firm lost the contract.

Lesson: NEVER test beyond what's agreed. STOP on warnings. Have a kill switch. Always test in staging if possible.

📈 Chapter 46 — Risk Assessment & CVSS Mastery

46.1 CVSS — Common Vulnerability Scoring System

CVSS v3.1 is the industry standard. Knowing how to compute it correctly is vital for accurate reporting.

46.2 CVSS v3.1 Vector Anatomy

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H = 9.8 Critical

Breakdown:
AV  = Attack Vector           (N=Network, A=Adjacent, L=Local, P=Physical)
AC  = Attack Complexity       (L=Low, H=High)
PR  = Privileges Required     (N=None, L=Low, H=High)
UI  = User Interaction        (N=None, R=Required)
S   = Scope                    (U=Unchanged, C=Changed)
C   = Confidentiality impact  (N=None, L=Low, H=High)
I   = Integrity impact        (N=None, L=Low, H=High)
A   = Availability impact     (N=None, L=Low, H=High)

46.3 Compute CVSS — Real Examples

46.3.1 SQL Injection in Login (Public Internet)

Vector: CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
= 9.8 (Critical)

Explanation: Network attack, low complexity, no privileges, no UI,
unaffected products, full disclosure + integrity + availability impact.

46.3.2 Stored XSS in Admin Tool

Vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:L/I:L/A:N
= 5.4 (Medium)

Explanation: Network attack, low complexity, requires admin login,
user interaction required (admin views page), scope changed, low impact
on C/I.

46.4 Severity vs Business Risk

CVSS = technical severity. Business risk = impact to YOUR organization's mission + data. A 10.0 SQLi in a marketing site matters less than a 5.4 XSS in your payment system.

46.5 Risk Matrix Template

Low ImpactMediumHigh Impact
High LikelihoodMedium High Critical
Medium LikelihoodLow Medium High
Low LikelihoodInformationalLow Medium

46.6 Tailoring CVSS — Adding Context

CVSS-B (Business) and CVSS-E (Environmental) metrics let you adjust for:

  • Confidentiality of impacted data (PII, PCI, PHI, IP)
  • Affected population size
  • Discoverability (public known, internal only)
  • Availability of mitigations

46.7 Real-Life Scenario: Why Always Think Beyond CVSS

📍 Scenario — When CVSS Lies

A 6.5 medium-rated IDOR vulnerability in a marketing application's lead capture form might be totally irrelevant. But the exact same CVSS in a healthcare patient lookup API = HIPAA breach + $50,000+ fine. Always contextualize.

47.2 Executive Summary — The Most Important 1 Page

C-Suite / Board reads ONLY this. It must convey:

  • What was tested, by whom, for how long
  • Overall security posture (Critical/Low/Improving)
  • Top 3–5 most critical issues in PLAIN english (no jargon!)
  • Business impact of EACH (e.g., "$1.5M breach possibility")
  • Recommended next steps (concrete actions)
  • Risk-graded comparison to industry/peers if possible

47.4 Sample Finding (Real-World)

FINDING 1: SQL INJECTION in /api/search

Severity

CVSS 9.8 (Critical) Business Risk: Complete database compromise — 2.4M user records exfiltrable. PCI-DSS violation risk.

Description

The q parameter of GET /api/search is concatenated directly into a SQL query without parameterization.

Affected Endpoint

https://target.com/api/search?q=<attacker>

Steps to Reproduce

# Step 1: Confirm normal
$ curl "https://target.com/api/search?q=phone"
# Returns: {"results": [...]}

# Step 2: Inject single quote
$ curl "https://target.com/api/search?q=phone'"
# Returns: 500 Internal Server Error

# Step 3: Confirm SQLi with boolean
$ curl "https://target.com/api/search?q=phone'+AND+1=1--"
# Returns: 200 OK
$ curl "https://target.com/api/search?q=phone'+AND+1=2--"
# Returns: 200 OK, empty results

# Step 4: Enumerate tables (UNION)
$ curl "https://target.com/api/search?q=test'+UNION+SELECT+NULL,table_name+FROM+information_schema.tables--"

Proof of Concept

Screenshot 1: img1_sqli_boolean.png

Screenshot 2: img2_sqli_union_dump.png — shows email table extracted.

Remediation

Use parameterized queries / prepared statements:

// VULNERABLE:
String q = request.getParameter("q");
String sql = "SELECT * FROM products WHERE name LIKE '%" + q + "%'";

// SECURE (Java):
String q = request.getParameter("q");
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM products WHERE name LIKE ?");
ps.setString(1, "%" + q + "%");
ResultSet rs = ps.executeQuery();

References

  • CWE-89: SQL Injection
  • OWASP A03:2021 — Injection
  • OWASP Cheat Sheet: Query Parameterization

47.5 Screenshot Best Practices

  • Always show the URL bar + timestamp + clock visible
  • Highlight sensitive data with a red box (still beachside next screenshot)
  • Capture terminal output with script command for reproducibility
  • Annotate with numbers (Step 1, Step 2, ...)

47.6 Reporting Anti-Patterns

❌ DON'T:
  • Describe findings buried in jargon — exec won't read
  • Use vendor template that hides criticals in lots of headers
  • Recommend vendor's product (looks like a sales pitch)
  • Be vague ("Update the input validation") — give exact code snippets
  • Lack reproducible PoC — client must verify
  • Ship report without executive summary
  • Forget to cite CVE, CWE, OWASP references
  • Forget timeline of testing (when, how long, who)

47.7 The Retest Report

After client's remediation, do a focused retest and produce a one-pager:

StatusMeaning
✓ FIXEDValidated fix in place, no re-test needed
⚠ PARTIALFix attempted but incomplete
↓ DOWNGRADEDRisk reduced (e.g., WAF added)
✗ NOT FIXEDStill vulnerable

  • Compliance = Following documented controls. Evidence-based.
  • VAPT = Technical validation. Adversary simulation.
  • Many companies pass compliance and still get breached. Because compliance != security.

51.5 First 90 Days as a New Director

  1. Days 1–30: Listen & Learn. Meet every stakeholder. Read prior reports. Audit existing tooling, processes, and team skills.
  2. Days 31–60: Quick wins. Pick 1–2 low-effort, high-impact improvements (tooling consolidation, a new testing checklist, better deliverable template).
  3. Days 61–90: Strategic plan. Draft a 12-month security roadmap. Present to leadership. Get budget approvals. Hire 1–2 missing skills.

51.7 The One Skill Nobody Teaches — Empathy

As a manager, you may one day fire a tester. As a director, you may have to tell the CEO the company has been breached. The technical skills taught in this book are 50%. The other 50% is emotional intelligence, empathy, and courage.

"A good manager gets the right things done. A great manager makes people better than they knew they could be." — paraphrased from Peter Drucker
