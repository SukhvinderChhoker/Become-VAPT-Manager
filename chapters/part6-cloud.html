35.5 Real AWS Pentest Workflow

10-step AWS Pentest Playbook

  1. Get scoped AWS accounts (read-only IAM user required)
  2. Enumerate identity — whoami, list-account, organizations
  3. Enumerate users, roles, policies with ScoutSuite + enumerate-iam
  4. Map attack paths — iam::privesc paths
  5. Enumerate S3 — public buckets, sensitive data
  6. Enumerate IAM users + access keys
  7. Enumerate EC2 + check public IPs, IMDSv1/v2, user-data, security groups
  8. Enumerate RDS — public accessibility, encryption
  9. Enumerate Lambda + Step Functions — secrets, env vars
  10. Try to escalate; document every step with screenshots

35.6 AWS Real-Life Scenario: Capital One Breach

📍 Scenario Recap: Capital One, 2019 — $190M Penalty

Root cause: SSRF in a misconfigured WAF EC2 instance → reached metadata service → WAF's overly-permissive role enabled cross-account S3 read → 106M customer records.

Pentest-stops-this checklist:

  • Deny 0.0.0.0/0 ingress + restrict IMDSv1
  • Role policies with least privilege
  • S3 account-level Block Public Access enabled
  • Continuous configuration scanning
  • Bug bounty program

36.5 Real-Life Scenario: Microsoft AI Studio Breach (2023)

📍 Scenario — Wiz Research found a 38TB Azure AI Studio exposure

A shared endpoint in Azure AI Studio gave open access to Microsoft internal training data — including sensitive customer information. The misconfiguration was accidentally exposed by a Microsoft engineer. Wiz discovered it through external recon of *.blob.core.windows.net buckets.

Lesson: Even cloud giants are vulnerable. Always configure "deny by default" + audit data exposure.

🏁 Chapter 38 — Real-Life Cloud Pentest Scenarios

📍 Master Scenario — "FinCloudX" Multi-Cloud (AWS + Azure)

FinCloudX uses AWS for prod + Azure for corporate. They hired us for a joint audit. We found:

  1. CVSS 9.6 Cross-account trust misconfigured — AWS prod role could be assumed by any Azure user
  2. CVSS 9.1 S3 bucket "fincloudx-kyc" public-read (3.4M PII records)
  3. CVSS 8.8 Lambda execution role had iam:* privileges
  4. CVSS 8.0 Azure tenant had 14 stale Global Admin accounts (ex-employees!)
  5. CVSS 7.0 IMDSv1 enabled on all EC2 — SSRF chain to creds possible
  6. CVSS 6.5 Storage account "fcxprodblob" allowed anonymous enumeration

Client CTO said: "We passed our SOC2 audit 2 months ago — how?" Answer: SOC2 audits typically don't check penetration depth — they check documented controls. This is why organizations need technical VAPT alongside compliance.

38.1 Cloud Pentest — Reporting Best Practices

  • Use exact CLI/API commands in evidence
  • Include screenshots with timestamp + cloud console URL
  • Map findings to CIS Benchmarks + Cloud Custodian Framework
  • Provide Terraform/ARM/GCP YAML remediation snippets
  • Include threats-outside-scope (e.g., DDoS, social eng) explicitly
