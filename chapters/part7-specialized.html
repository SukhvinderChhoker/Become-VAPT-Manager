39.2 The IoT Pentest Methodology (PTES-IoT)

7 phases

  1. Information gathering — Google, FCC ID lookup, manuals, FCC teardown sites
  2. Firmware acquisition — From vendor site, FCC filings, BitTorrent
  3. Device teardown — UART ports, JTAG, debug pads
  4. Firmware analysis — Binwalk, Ghidra, strings
  5. Network reconnaissance — Mobile app, cloud APIs
  6. Exploitation — Protocol fuzzing, credential testing
  7. Reporting

39.3 Firmware Analysis Tools & Workflow

# Step 1: Get the firmware
$ wget https://vendor.com/firmware_v2.bin

# Step 2: Identify it
$ file firmware_v2.bin
$ binwalk firmware_v2.bin
# Output: DECIMAL    HEXADECIMAL  DESCRIPTION
# 0       0x0         uImage header
# 64      0x40        Linux kernel ...

# Step 3: Extract filesystem
$ binwalk -e firmware_v2.bin
# → _firmware_v2.bin.extracted/

# Step 4: Look for secrets
$ grep -rE 'password|secret|key|token' _firmware_v2.bin.extracted/
$ find . -name "*.conf"   # configs often leak creds
$ cat etc/shadow

# Step 5: Disassemble binaries
$ ghidra    # GUI
$ radare2 -A ./bin/httpd     # CLI

# Step 6: Check for hard-coded keys / backdoors
# Common pattern: if (strcmp(input, "AK47") == 0) root_shell();

39.5 Real-Life Scenario: Mirai Botnet Attack

📍 Scenario — Mirai's Origin (2016)

Mirai malware scanned the internet for IoT devices running telnet on port 23, brute-forced them with a list of ~60 default username/password combos (root:root, admin:admin, support:support, etc.), and recruited them into a 600,000-strong botnet that DDoS-ed Dyn DNS — taking down Twitter, Netflix, Reddit, and GitHub for hours.

Default credentials in IoT devices caused a global outage. Even your IP camera may have been part of that botnet.

🖥️ Chapter 41 — Thick Client VAPT

41.1 What is a Thick Client?

Desktop applications installed on a user's machine — Java Swing, .NET WPF, Electron, Delphi, Qt. Examples: trading workstations, banking software, IDEs.

41.2 Thick Client Attack Methodology

5-Step Thick Client Pentest

  1. Recon — Strings, file analysis, dependency check
  2. Decompile — Java: jadx; .NET: dnSpy/ILSpy; C++: Ghidra
  3. Inspect traffic — Proxy through Burp (sometimes via proxy config)
  4. Test backend APIs — Often have IDOR / SQLi
  5. Local attack — Registry, filesystem, DLL hijacking, memory

41.3 Java (.jar) Thick Client

# Decompile

$ jadx app.jar

# Inspect config files (often shipped in JAR!)

42.3 OT Pentest Methodology

OT Pentest Phases

  1. Asset discovery — Passive only! (active causes fault)
  2. Fingerprinting — Modbus, DNP3, S7Comm, IEC 61850, BACnet
  3. Network segmentation check — IT-OT boundary
  4. Wireless assessment — Field wireless sensors
  5. Configuration review — Engineering workstations, HMI
  6. Replay attacks — Capture command → replay (very dangerous!)
  7. Fuzzing against replica PLC — Use clones in lab only

44.3 Solidity — Famous Vulnerable Contract

// Vulnerable: Reentrancy
contract Bank {
    mapping(address => uint) balances;

    function deposit() public payable { balances[msg.sender] += msg.value; }

    function withdraw(uint amount) public {
        require(balances[msg.sender] >= amount);
        (bool sent,) = msg.sender.call{value: amount}("");
        // ← CALL triggers recipient's fallback function
        // Attacker.recv() calls withdraw() again
        // balance never checked before send?
        require(sent);
        balances[msg.sender] -= amount;
    }
}

// Fixed: checks-effects-interactions pattern
function withdraw(uint amount) public {
    require(balances[msg.sender] >= amount);
    balances[msg.sender] -= amount;       // ← STATE FIRST
    (bool sent,) = msg.sender.call{value: amount}("");
    require(sent);
}

44.5 Real-Life Scenario: Ronin Bridge Hack

📍 Scenario — Axie Infinity's Ronin Bridge (March 2022, $625M)

Lazarus Group (North Korea-linked APT) compromised 5 of 9 validator private keys on Sky Mavis's Ronin Bridge. Five keys was enough to forge withdrawals. They stole 625M USD in ETH/USDC — the second-largest crypto hack ever. North Korea used the funds to fund weapons programs.

The breach was a social engineering + ops security failure, not a code bug. Lesson: even in crypto, the human is the weakest link.
